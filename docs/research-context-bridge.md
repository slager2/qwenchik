# Explicit Deep Research context in Chat

`POST /api/conversations/{conversationID}/messages` optionally accepts `research_run_id`. It is valid only for a new `chat` send and a terminal research run belonging to that same conversation. The service derives a compact bridge from the stored final assistant message, citation-verification metadata and owned evidence; the caller cannot submit bridge claims, citations, warnings or source metadata directly. SQLite independently rechecks run ownership/status, verification references, evidence ownership, successful HTTP status, quality flags, canonical URL and the 8 KiB serialized bound.

The bridge is stored in the existing user-message `metadata_json` alongside its `research_run_id`; it creates no table or migration. Only individually cited claims from `supported` verification are carried as claims. A `fallback_excerpts` result carries no claims or raw excerpts, only source links and a fixed warning. The ordinary Chat run receives this object only for the selected user message, with an explicit untrusted-reference instruction, before the current user request. It does not fetch again or claim independent verification. The UI offers explicit activation and clearing; each request includes the run ID only while Chat mode is selected. Historical evidence is fetched through a conversation-local run-ID cache with concurrent request coalescing; errors remain cached until the user explicitly retries.
