# Event and SSE contract

## Durable envelope

```json
{
  "id": "event_uuid",
  "task_id": "task_uuid",
  "seq": 42,
  "type": "task.status_changed",
  "schema_version": 1,
  "created_at": "RFC3339",
  "stage": "planning",
  "visibility": "user",
  "payload": {}
}
```

`seq` is monotonically increasing within a task. Events are append-only. A task state mutation and its event are committed in the same transaction. Internal/audit events are not sent to user-facing SSE without explicit redaction.

Public event types include `task.created`, `task.status_changed`, `task.recovered`, `message.created`, `message.delta`, `plan.created`, `step.started`, `step.completed`, `step.skipped`, `tool.started`, `tool.completed`, `tool.failed`, `search.provider`, `evidence.created`, `artifact.created`, `approval.requested`, `approval.approved`, `approval.rejected`, `approval.expired`, `task.completed`, `task.failed`, and `task.cancelled`. `step.skipped` records a conditional plan step that was intentionally not executed. `checkpoint.saved`, `policy.decision`, `approval.consumed`, and `memory.retrieved` remain internal/audit. This list is additive; existing event types and payloads retain their meanings.

`inference.summary` is an internal event written at most once per finished LLM invocation when bounded final inference telemetry is available. It contains only invocation identity/status and validated token/timing metrics; prompt and response text, system/GPU samples, streaming ticks, and provider error bodies are excluded. It uses the existing event journal and adds no SQL migration.

`message.delta` is emitted only for the final user-facing synthesis and only with `visibility: "user"`. Its payload is `{ "stream_id": string, "message_id": string, "chunk_index": number, "delta": string }`. Chunk indexes start at zero and increase consecutively for a stream. Each persisted delta is bounded; stream IDs are fresh for each synthesis attempt, including citation corrections. Deltas are provisional text, not a finalized assistant message or lifecycle authority. Only after citation validation succeeds does `CompleteTask` persist the canonical assistant message and its `message.created` event, using the final stream's `message_id`.

## SSE

- `GET /api/tasks/{task_id}/events/stream`
- `GET /api/runs/{run_id}/events/stream` aliases the conversation run ID to its task event journal.
- `id:` equals durable task `seq`; `event:` is an allowlisted event type; `data:` is the envelope JSON.
- `Last-Event-ID` replays events after the supplied sequence in ascending order.
- Heartbeat comments are emitted while waiting; stream buffering and replay are bounded.
- A newly connected client can fetch events with `GET /api/tasks/{task_id}/events?after=N` before subscribing.
- Terminal task events are persisted and delivered like all other events.

The durable envelope/cursor rules above apply to committed journal events. Runtime streams additionally send non-durable `snapshot`, `runtime_snapshot`, `inference_progress`, and `resource_warning` frames without an event ID or sequence number. They are coalesced status snapshots, do not advance the durable cursor, and are not replayed from event history. `GET /api/runs/{run_id}/runtime` includes the latest persisted inference summary when one is available.

No model-generated token or progress event is trusted as lifecycle state. Streamed model text is exposed only as provisional `message.delta` events and is not an event authority.

## Search observability

`search.provider` and `tool.failed` are public only with `visibility: "user"`. Internal and audit versions remain private. Both REST event history and SSE apply the same diagnostic projection: raw error messages, response bodies, credentials, request arguments, and unknown fields are omitted. Diagnostic messages are generated by the API from classifications, never copied from provider responses.

`search.provider` describes an actual attempt, rather than configuration or a speculative fallback. Its payload contains `provider`, `state`, `code`, `message`, `retryable`, `http_status`, `latency_ms`, `checked_at`, `result_count`, and `distinct_domains`. `tool.failed` may carry the same safe diagnostics, `tool`, `step_id`, `error_code`, and an `outcomes` or `providers` array of projected provider diagnostics. These events do not establish task lifecycle state.

Provider states include `healthy`, `degraded`, `blocked`, `unavailable`, `malformed`, and `misconfigured`. Codes distinguish `search_no_results` (a valid empty response), `search_filtered_by_policy` (results excluded by policy), `provider_blocked` (access denial or challenge), and `search_unavailable`. In particular, `degraded` alone does not mean an empty response. Retryability is reported separately from state. A provider returning hits does not imply that the task has enough independent evidence.

`task.failed` remains authoritative for failure. Its user-facing `message`, `error_code`, `verification_summary`, and string-array `missing` explain unmet criteria. The UI displays this failure prominently even when an earlier synthesis, partial evidence, or artifact exists.

`verification.completed` reports evidence readiness independently from final citation review. Its `verdict` is `PASS`, `PARTIAL`, `RESEARCH`, `UNCERTAIN`, or `BLOCK`; `missing` contains critical blockers, while `supplementary_missing` contains non-blocking criteria that were not met. The bounded `criteria` array records each criterion's step/index, critical-or-supplementary classification, met state, and task-owned evidence IDs. A `PARTIAL` readiness verdict yields a completed run with `terminal_outcome: "partial"` when a safe answer is committed; it does not mean that citation review failed.

## Provider and readiness endpoints

`GET /api/providers` is read-only and performs no probes. `search.providers` contains `searxng`, `tavily`, and `duckduckgo`. Each entry separates `configured` and `enabled` from `health`, nullable `last_checked`, nullable `last_outcome`, and observed latency/retryability. `status` retains the configuration status for compatibility. `health: "not_checked"` and null observation fields mean no actual attempt has been observed. A composite placeholder with `provider_not_checked` is not an observation. Disabled providers can retain historical outcomes without becoming enabled.

Endpoints exposed to clients contain only scheme and authority, with userinfo, path, query, and fragment removed. DuckDuckGo uses a fixed public endpoint. Last outcomes use the same safe diagnostic projection as events.

Startup attaches the configured composite's `HealthSnapshot` through `Server.SetSearchDiagnostics`. `Server.SetDDGEnabled` mirrors the main configuration privacy switch; the default remains enabled for compatibility. Configuration and startup wiring are owned by the main CLI.

`GET /api/doctor` reports application, attached worker, database connection, artifact reader, frontend, sandbox, and model checks, plus `providers` with actual last search outcomes. An absent worker is an error, not a ready worker. Database ping and an attached artifact reader establish connection/attachment only, not a write or artifact-integrity test. Configured search is never promoted to healthy without an observation. Doctor does not probe Tavily or DuckDuckGo. A configured loopback SearXNG may receive a local search probe bounded to two seconds; its separate `search_probe` result does not overwrite the composite's last attempt.

The frontend distinguishes initial SSE connection, open stream, reconnecting transport, and terminal closure. Terminal task state closes the client stream and is shown as finished rather than reconnecting. Provider cards are available before starting a task and mark refresh failures as potentially stale data.
