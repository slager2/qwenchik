# Web research and evidence contract

## Phase 1 session contract

New session-backed conversation research runs use immutable policy, budget, and local model snapshots while executing the existing fixed-plan worker. `RESEARCH_DEFAULT_PROFILE=standard` is the default; `research_settings.profile` selects a named budget. `RESEARCH_ADAPTIVE_ENABLED=false` is required for Phase 1: `true` returns a configuration error until Phase 3. Profile rounds, questions, and stagnation fields do not enable adaptive execution.

The canonical profile values are owned by `domain.ResearchBudgetForProfile` and `domain.DefaultResearchPolicy` in `internal/domain/research_defaults.go`:

| Profile | Wall ceiling, seconds | Rounds | Nominal queries | Queries with default server cap | Fetches | Logical LLM calls | Evidence | Questions created / accepted | Stagnant rounds |
| --- | ---: | ---: | ---: | ---: | ---: | ---: | ---: | ---: | ---: |
| `quick` | 300 | 1 | 4 | 4 | 4 | 10 | 4 | 6 / 2 | 1 |
| `standard` | 1800 | 3 | 8 | 8 | 8 | 24 | 8 | 16 / 6 | 2 |
| `deep_laptop` | 7200 | 5 | 16 | 12 | 12 | 40 | 12 | 30 / 10 | 2 |
| `long_laptop` | 14400 | 8 | 32 | 12 | 24 | 72 | 24 | 60 / 20 | 2 |
| `overnight_laptop` | 21600 | 10 | 48 | 12 | 36 | 96 | 32 | 80 / 24 | 2 |

All profiles have a nominal `MaxSteps=12`, clamped by trusted `MAX_STEPS`. Queries are `min(profile.MaxSearchQueries, MAX_SEARCH_QUERIES)`; the server default is 12, so long/overnight retain nominal ceilings of 32/48 while their default effective query caps are both 12. Citation budgets retain the legacy Phase 1 envelope: `MaxCitationSources=8` (`quick=4`), `MaxCitationClaims=8` for all profiles. Section-based generation is not implemented. These are hard upper bounds, not promised counts, report sections, or elapsed runtimes.

`research_settings.time_budget_seconds` must be an integral 60–21600 seconds. It replaces only the run's wall allowance, including when extending a shorter profile; it does not expand other counters or output-token caps. Submission stores an absolute deadline shared by the task and research session. Queue time and process downtime consume it; same-run recovery does not restart it. `TASK_TIMEOUT_SECONDS` remains the legacy task interval, default 7200 and accepted range 1–21600.

Before each session model invocation, storage atomically reserves a logical LLM call and its initial model HTTP attempt. JSON-schema incompatibility may permit one JSON-mode fallback, reserved as an extra HTTP attempt before dispatch. `LLMCalls <= MaxLLMCalls` and `HTTPAttempts <= 2 * MaxLLMCalls`; HTTP attempts here count model completion requests, not search-provider or source-download traffic. Repairs that invoke the model again consume another logical reservation. Errors and restart do not refund reservations. Search/fetch operations are also reserved before their tool execution, with existing cumulative-byte/evidence checks.

A new send freezes the validated conversation sampling/output overrides into the model snapshot. The worker applies the saved loopback endpoint, model identifier, output cap, stop sequences, temperature, and top-p to both `Complete` and `Stream`, using explicit sampling-set flags to preserve zero temperature. The citation critic sets `TemperatureSet=true` explicitly, independently of a nonzero run temperature. Research snapshots live in `research_sessions`; Chat snapshots live in existing versioned checkpoints without a research-session row. Snapshots use `PromptVersion=local-research-v1`, `SchemaVersion=1`, and empty stop sequences because the conversation API does not expose that setting. Endpoint/model/credential/stop overrides are not conversation settings; current client credentials are not persisted in the snapshot.

Retry/continue of a session-backed run clones the prior immutable profile, policy, budget, and model snapshot into a new run/session with new counters and a new deadline. The previous session stays intact. Same-run restart reuses its existing session and reservations. At execution/recovery entry, changed snapshotted fetch/PDF policy or insufficient current model context fails with `research_runtime_changed`; the worker does not silently substitute new resource/security limits. This comparison uses startup-constructed runtime settings, not a watcher of edited `.env` files.

Migration `009_research_sessions.sql` adds one table, `research_sessions`, with a unique task foreign key, conversation foreign key, goal/status/profile, immutable policy/budget/model JSON, mutable counter JSON, phase/round/plan/stop fields, and lifecycle/deadline timestamps; it also adds the conversation index. Existing tasks, messages, checkpoints, events, evidence, artifacts, and FTS data are not backfilled into sessions. Runs with no session retain legacy behavior. Round/question frontier state belongs in versioned checkpoint JSON; Phase 1 adds no round/question tables. Migration tests from versions 001–008, full Go tests/vet/race and the bounded deployed snapshot smoke passed; details are in [Research Phase 1](../research-phase1.md#verification-results).

Accepted conversation modes remain `chat` and `research`, with existing web-enabled and tool-policy restrictions. Phase 1 adds no external judge calls, notification system, or sleep/power/runtime-lifecycle guards. Adaptive research, section generation, and session-specific API/UI exposure are later-phase work; session exposure belongs to Phase 6.

## Providers

- Discovery includes DuckDuckGo unless `SEARCH_ENABLE_DDG=false`. It is enabled by default for convenience; README, environment example and UI disclose external processing. Optional providers are local SearXNG JSON through `SEARXNG_URL` and Tavily through `TAVILY_API_KEY`. SearXNG accepts only loopback hosts; `compose.searxng.yml` provides a loopback-only instance with JSON enabled. Tavily uses a fixed HTTPS endpoint, and its key is never returned by diagnostics or included in error messages.
- `SEARCH_PROVIDER_POLICY=local_primary` is the startup default; only `local_primary` and `parallel` are accepted. Local SearXNG runs first. At least two independent registrable source domains suppress fallback, including when the primary reports degraded but usable results. Otherwise configured Tavily is attempted once; setting its key explicitly opts into external discovery. Without SearXNG, configured Tavily becomes primary. DuckDuckGo is attempted only when enabled and preceding results still lack two independent domains. Usable primary hits retain priority and survive secondary failure. Hits retain their provider/query metadata; canonical duplicates keep the first hit. Outcomes describe attempted providers only; health snapshots keep unattempted providers `configured`, never implicitly healthy.
- A query has one shared collection deadline of at most 12 seconds, bounded by its caller. An attempt with a possible fallback receives at most 8 seconds or 60% of the remaining allowance, whichever is smaller; the final attempt receives the remainder. Each provider is attempted at most once. Parent cancellation dominates partial success. `parallel` explicitly restores the existing concurrent Composite behavior and round-robin merge. Both policies filter against `ALLOWED_DOMAINS`, deduplicate canonical URLs, and cap results globally. With zero usable hits, any provider failure is an outage rather than a valid empty search; only genuine all-valid-empty responses enter query broadening.
- Provider strategy is global startup/provider configuration. The current version-1 immutable per-run research profile does not snapshot it; changing this startup setting affects subsequent execution, including recovered runs, without changing that profile schema.
- Research queries are generated from the task's bounded questions; the backend does not inject topic-specific query templates or authority-domain lists. `ALLOWED_DOMAINS` remains a hard restriction.
- `SearchWithDiagnostics` returns hits and bounded per-provider outcomes. Health snapshots distinguish configuration from last observed `healthy`, `degraded`, `unavailable`, `blocked`, `malformed`, and `misconfigured` responses. An untested configured provider is not healthy. A mixed provider failure and empty response with zero usable hits is an outage, not a valid zero-result search.
- Query terms are sent to DuckDuckGo by default, to Tavily when configured, and to SearXNG's enabled public search engines. `qagent doctor` does not make a Tavily or DuckDuckGo request; it reports the built-in fallback and configured provider status without spending a search request.
- `search` returns bounded title, URL, score, publication time, and snippet data. Search snippets are untrusted and are not evidence by themselves.
- Search-intent tasks with no user URL require the search tool and a plan containing both `search` and `fetch`; an unavailable provider is surfaced as `search_unavailable`, not treated as an empty successful search.
- Generic web research plans 2–3 independent search facets and 2–4 distinct source fetches. The first facet may trigger one durable broader retry only after a successful zero-hit result; this retry is not a planned facet. Optional remaining search/fetch steps are skipped after at least two distinct source sites are fetched and the search facets/minimum evidence floor are met. The backend checks the user/task acceptance criteria and requires evidence before source-backed claims.
- Search connection/HTTP failures and oversized search responses are surfaced with search-specific error codes; fetch-size failures remain distinct.
- Genuine empty searches may trigger one broader initial query, then end as `search_no_results`. A challenge, invalid key, transport error, malformed response, and all-results-filtered policy outcome do not trigger query broadening. Provider diagnostics are persisted as sanitized `search.provider` events; query text and response bodies are excluded.
- `fetch_url` accepts only a URL present in the task/user messages or returned by a prior search action.
- Direct HTTP fetch supports static HTML, XHTML, plain text, JSON, and bounded PDF input. HTML is parsed locally; `script`, `style`, navigation, and form content are excluded from extracted text.
- HTML extraction prefers substantial JSON-LD content, then strict-JSON Next/Nuxt hydration, metadata and scoped semantic DOM. No JavaScript is executed. Recursion, structured input size and text length are bounded.
- Fetch candidates are individually authorized. Source-level response/PDF byte, page, text, parser, timeout or resource failures terminate that candidate and may permit another authorized candidate. They are distinct from cumulative task budget exhaustion. Cancellation, whole-task timeout, unknown outcome, policy rejection and a plan requiring the exact supplied URL must not silently choose an alternative. Bytes actually read, including failed downloads/extractions, count toward the task budget; header-only rejection counts zero. Insufficient evidence is reported rather than synthesized into unsupported facts.
- The repair profile separates task budget 134,217,728 bytes (128 MiB), ordinary source limit 16,777,216 bytes (16 MiB), and PDF limit 67,108,864 bytes (64 MiB). PDF parsing retains 20 pages, 50,000 Unicode text characters, a 30-second extraction deadline, 120-second download deadline, bounded output, and isolated resource limits of 512 MiB memory, 64 MiB tmpfs, 1 CPU and 32 PIDs. Artifact, sandbox file and temporary-disk limits remain independent. The running doctor's injected policy is authoritative; see the repair report for integration/validation status.
- PDF isolation requires a digest-pinned Alpine/Poppler image, verified local rootless Docker, immutable image ID/digest, `--pull=never`, no network, read-only root, dropped capabilities, no-new-privileges, non-root UID, and CPU/memory/PID/output limits with forced cleanup. Rootful Docker is insufficient. Unsandboxed pure-Go fallback is disabled by default. When explicitly permitted, it runs in a re-executed bounded helper process, without inherited application secrets; a Go runtime memory target is not OS/cgroup isolation. Missing isolation with fallback forbidden yields `pdf_extractor_unavailable`. Malformed, encrypted, empty-text, oversized, timed-out or output-overflowing PDFs produce no partial evidence. JS-only pages and Playwright remain unimplemented.
- PDF URLs with a `.pdf` path are capability-checked before invoking the fetcher. For other URLs, `application/pdf` response headers are checked before reading the body; if MIME is absent or incorrect, a bounded first-1024-byte signature preview is checked before the remaining body is downloaded or spooled. The preview bytes count toward source/task byte accounting. PDF signatures may occur within that initial 1024-byte range.
- `FETCH_TEMP_DIR` resolves relative paths from the process working directory. Its final directory must be a dedicated, current-user-owned mode-0700 directory; filesystem roots, the working directory/home and their ancestors, and existing directories with broader permissions are rejected without changing their modes. Linux additionally rejects extended POSIX ACLs; non-Windows Unix systems without ACL validation fail closed. Changing the root does not migrate stale leases from the previous root; clean that private directory only after all processes using it have stopped. This setting covers file-backed fetched PDFs, not unrelated bounded scratch files used by other subsystems.

## Network policy

The fetcher uses no proxy, allows only HTTP/HTTPS on ports 80/443, rejects URL credentials and credential-like query parameters, enforces an optional `ALLOWED_DOMAINS` suffix allowlist, checks all DNS answers, and re-resolves/revalidates immediately before dialing each redirect target. Loopback, private, link-local, reserved, multicast, unspecified, and non-global IP ranges are denied. Redirect depth, request time, response bytes, and MIME types are bounded.

### DNS source failures

DNS lookup failures during source authorization or connection-time DNS revalidation retain their operational identity and are published as `fetch_dns_failed`, not `invalid_tool_arguments` or SSRF rejection. Authorization still denies the failing source; the worker records a zero-body source failure and tries another approved candidate when the plan permits alternatives. Private/non-public addresses, malformed tool arguments, approval failures, parent cancellation/deadlines and required explicit URLs do not gain this fallback permission. A failed source cannot supply evidence or citations.

The incident pattern—search discovery succeeds, then DNS fails when the source is revalidated—is covered by a local full-worker integration test that completes with two independently fetched evidence records and a partial-source warning. Tests also cover required URLs, cancellation and connection-time DNS errors. Network-dependent behavior of a particular public website is not simulated as a successful live download.

## Provenance

Each fetched source receives a SHA-256 content hash, retrieval time, original and canonical URL, provider/query, title, HTTP status, extraction method, local raw/text artifact references, excerpt, quote span, quality flags, and taint label. Duplicate `(task, canonical URL, content hash)` records are deduplicated. The finalizer may cite only evidence IDs present in the current task state; backend citation validation rejects unknown or missing source IDs when research evidence was used.

Artifacts are written atomically below the configured local artifact root with task-owned IDs and size limits. SQLite stores metadata and references only; API/UI expose metadata and excerpts, and the artifact download route resolves task-scoped IDs rather than filesystem paths.

## Source failure projection and replay

`tool.failed` for `fetch_url` and the allowlisted `source.*` lifecycle events project the same typed public fields: `attempt_id`, numeric `plan_attempt`, `step_id`, `tool`, safe `target_url` or `source_fingerprint`, `status`, `error_code`, `retryable`, `try_next_source`, `user_retry_task`, optional `declared_bytes`, `effective_limit_bytes`, `fetched_bytes`, normalized `mime_type`, `remaining_candidates`, RFC3339 `timestamp`, and `fallback_attempted`. Legacy `code`/`failure` normalize to `error_code`. Unknown codes become `source_failed`; arbitrary messages/errors/stderr and credential-bearing URLs are excluded. Diagnostic byte values are nonnegative integers capped at 1 TiB; candidate/plan counts are capped at 1,000,000. Missing values remain unknown, including declared length.

`task_fetch_budget_exceeded` is task-level. Source-level codes include `source_response_too_large`, `pdf_source_too_large`, `pdf_extraction_input_too_large`, `pdf_page_limit_exceeded`, `pdf_text_limit_exceeded`, `pdf_resource_exceeded`, `pdf_timeout`, `pdf_extractor_unavailable`, `pdf_malformed`, and `pdf_encrypted`. `fetch_outcome_unknown` requires recovery rather than blind replay. The legacy `fetch_budget_exceeded` does not identify which old limit was hit.

`/api/runs/:id/sources` merges canonical URL/fingerprint identity, keeps title/snippet/provider, and creates explicit-user-URL cards without requiring discovery. Audit/user copies of one attempt update one card; repeated starts for the same terminal attempt cannot regress it to fetching. `event_seq` allows the frontend to reconcile snapshots with replay. `timestamp` is the source lifecycle time, distinct from evidence retrieval time. Failed/rejected cards do not become citation references. Independently fetched evidence stays visible through another source's failure or source-endpoint outage.

The UI distinguishes zero body bytes from positive bytes read (which alone do not prove a complete download), and displays decimal MB and binary MiB alongside exact bytes. `try_next_source=true` permits another candidate but does not prove it was attempted. A backend `fallback_attempted=true` or a subsequent different candidate/attempt in the same plan attempt and step confirms an attempt, not successful extraction. Searches run as separate planned steps are not same-candidate fallback. Partial source coverage does not itself authorize a completed/verified answer.

`research.warning` with `code=sources_skipped` and boolean `partial=true` preserves a partial-coverage warning even when the run is completed and the currently visible source snapshot contains only accepted sources. Its `source_failures` list uses the same source sanitizer, deduplicates `attempt_id`, retains exact allowlisted error codes and zero byte counts, and exposes at most 256 failures (`source_failures_truncated=true` when bounded). Raw warning messages and arbitrary nested fields are removed. The UI uses a backend-owned partial flag and a fixed explanation, keeping accepted evidence independent.

CLI doctor delegates effective-policy reporting to one bounded running-app `/api/doctor` response. It filters keys/types/ranges and check statuses again, discards raw check messages/outcomes, and does not re-probe the model or replace missing server policy with local configuration. Caller cancellation or malformed/oversized/redirect responses produce an unknown-policy warning. Standalone policy/runtime checks are used only when no app responds; standalone inference still requires worker ownership.
